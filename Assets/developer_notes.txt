------------------------
SUMMARY
------------------------
A 3d puzzle-platformer-collectathon game with a grapple hook
central mechanic.  Attacks are technically possible, but not
emphasized, and combat is not difficult



------------------------
LAST SESSION
------------------------
Started work on refactoring the player prefab.  There is now an 
IoC container for the player object to help manage dependencies.
The camera is refactored into a camera manager, which uses the command
pattern to create camera target scripts.  The camera manager repositions
the camera, while the camera target determines where the camera should
look at and reposition.  Detecting mouse movements was extracted
out of the camera controller and into its own script, which implements
a mouse controller interface.  This interface will help support
switching between controller and keyboard in the future.

- Next session, the player movement controller should be refactored
so it doesn't depend on the camera, it should use the IoC container,
and movement should be mildly refactored to support snapping to 
moving platforms.  This will be a good opportunity to fix gravity
bugs

- as a todo, the camera controller currently caches a reference
to the mouseManager.  It should propbably not cache a reference
in the case the player switches from keyboard to controller mid-gameplay,
which could result in a null pointer exception.  Should probably
implement an input manager.  Also, the mouseManager will likely need
to keep track of the mouse context, so clicks arent detected inside menus, etc.

- Another todo, camera pan and zoom speed are stored as local variables.
That should be refactored to be player preferences.

UP NEXT
------------------------
- Decomplexify the camera controller so it doesn't have 2
follow objects.  Make it lerp to a target position rather
than set its transform position.  This will reduce camera
jitter.   Give the camera the option to be first person or 
third person, and create more complex camera animation 
effects for cinematic moments in gameplay. A main goal should 
be to make the camera code modular and reusable for future 
games I build

- Refactor and simplify character movement scripts.  Should
account for moving platforms, slippery surfaces(?), and
multiple movement modes (running, water skating, etc.).
Create a setting for allowing movement midair vs. not for
gameplay testing.

- Make level loading more seamless by either having a large
level that disables objects not in a bounding box, or by
having asynchronous multi-level loading enabled

- Saving / loading.  Currently uses a tree structure that
should be refactored into a dictionary
